# databricks (Data A + Data B)
- `ingestion/` (Data A): adapters, landing writer, Bronze stream.
- `features/` (Data B): PURE pandas, no Spark.
  - `minute_features.py` (Silver), `baselines.py` (causal robust z), `state.py` (Gold + `row_to_wearable_state`), `synthetic.py` (test data, synthetic).
  - `quality_policy.py`: explicit, config-driven rules for which Bronze rows feed `minute_features`. HR/EDA use `quality=="valid"` only, plus our own plausibility range (defense in depth). ACC usability is controlled by `QualityPolicy.acc_scale_assumption` (`"mock_assume_1_64g"` for `synthetic_fixture` runs -- rows flagged ONLY for unverified units are used anyway, since the mock is built at that scale; `"exclude_until_verified"` for `recorded_replay` runs -- ALL ACC rows excluded, and Gold's `activity_level`/`estimated_rest_minutes` null with reason `acc_units_unverified` instead of the generic `acc_unavailable`).
  - `bronze_adapter.py`: Bronze-shaped rows (NormalizedEvent fields plus `flag_reason`) -> the hr/eda/acc frames `minute_features` expects, after applying the quality policy. Also builds those Bronze-shaped rows directly from the raw BIG IDEAs/mock CSVs (`bronze_rows_for_participant`), so Data B can run end to end before Data A's real adapter and Bronze table exist. The exact `flag_reason` strings there are Data B's own, pending confirmation from Data A's adapter (only `hr_above_engineering_range` is confirmed verbatim); see `docs/decisions.md`.
  - `run_local.py`: raw CSVs -> Bronze rows -> quality policy -> silver/gold + tuning summary. `--shift-days` maps a recording onto the scenario replay clock by adding whole days to LOCAL wall time before localizing (never a fixed UTC offset, since Feb is EST and Oct is EDT); `--source-kind` selects the quality policy default; `--history-start`/`--segment-end` bound the run (local time, before the shift).
- `streaming/` (Data B): Spark wrappers (M2). `batch.py` is the pure-pandas core (no pyspark import, unit tested): `process_silver_features_batch` runs `bronze_adapter`/`quality_policy` then `minute_features` for newly finalized minutes; `process_silver_baseline_batch` recomputes `add_baselines` from the run's first minute and returns only the new rows; `process_gold_batch` runs `build_gold` over all baselined Silver and returns only the rows after the last written `as_of`. `silver_stream.py`/`gold_stream.py` are thin `foreachBatch` glue around those functions (readStream/writeStream, MERGE via `merge.py`'s Delta helpers); `run_demo.py` is the notebook/job entry point that creates tables, runs both streams to catch up, and prints a verification summary. All require pyspark/delta-spark and raise a clear `ImportError` outside a Databricks runtime rather than being silently importable. Not yet smoke-tested against a real Spark session -- see `docs/databricks-runbook.md` for how to run it, `databricks/sql/verify_gold.sql` for the SQL checks, and `tests/test_streaming_idempotency.py` for the Spark-free idempotency check of the batch logic it calls.
- `sql/`: DDL (`ddl_bronze.sql` Data A; `ddl_silver.sql`, `ddl_gold.sql` Data B) and backend read queries, plus `verify_gold.sql` (Data B's post-run checks).
Gold row -> contract: `databricks.features.state.row_to_wearable_state(row)`.
